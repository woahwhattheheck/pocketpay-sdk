# Payment-Period Conduct

Contributors should keep review and campaign communication focused, evidence-based, and respectful.

Before asking about a contribution's campaign status:

- Re-read the issue acceptance criteria and review your own diff objectively.
- Record the implementation, relevant test or documentation evidence, CI status, and known limitations on the pull request.
- Check whether the question has already been answered on the issue, pull request, or campaign channel.
- Use one clear follow-up for an unresolved decision instead of repeating the same request across multiple threads.
- Follow the current GrantFox process for contribution evaluation and campaign questions.
- Do not treat a merge, claim, or campaign label as an automatic approval.

Repeated identical messages make review harder. A later follow-up is useful when it adds new evidence, reports a material status change, or asks a specific unanswered question.

## Self-review checklist

Before following up, confirm that:

- [ ] Every acceptance criterion is addressed or clearly marked incomplete.
- [ ] The pull request explains what changed and why.
- [ ] Required validation evidence is recorded, or a docs-only exception is clear.
- [ ] CI status is reported accurately.
- [ ] Known limitations are documented.
- [ ] The follow-up asks for a specific unresolved decision.

See the [Evaluation Readiness Index](./evaluation-readiness.md), [Contribution Quality Gate](./contribution-quality-gate.md), and [Contributor Self-Review Form](../.github/checklists/contributor-self-review.template.md) for the repository's review expectations.
